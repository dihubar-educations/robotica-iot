Configurar el IDE de Arduino para el ESP8266 y resolver el driver CH340

Dos partes: primero se prepara el IDE para programar el NodeMCU; después, si la carga falla, se vuelve al driver CH340 de 2019. Volver a los simuladores.

01

Agregar el ESP8266 al IDE de Arduino

El IDE trae de fábrica las placas Arduino, pero no el ESP8266. Hay que indicarle de dónde bajar su soporte. Se hace una sola vez por computadora y, como baja unos 150 MB, conviene hacerlo antes de la clase.

  1. Instalá el Arduino IDE 2.x desde arduino.cc y abrilo.

  2. Entrá en Archivo → Preferencias. En el campo URL adicionales del gestor de placas (Additional boards manager URLs) pegá esta dirección y aceptá:

    http://arduino.esp8266.com/stable/package_esp8266com_index.json

  3. Abrí Herramientas → Placa → Gestor de placas (o el ícono de placa en la barra izquierda). Buscá esp8266 e instalá esp8266 by ESP8266 Community. Los programas de este curso están verificados con la versión 3.1.2.

  4. Elegí la placa en Herramientas → Placa → esp8266 → NodeMCU 1.0 (ESP-12E Module).

  5. Conectá el NodeMCU con un cable USB de datos y elegí el puerto en Herramientas → Puerto → COM…. Si no aparece ningún puerto COM, pasá a la parte 3.

  6. En Herramientas → Upload Speed, si la carga falla con 921600, bajala a 115200: es más lenta pero más tolerante con cables y placas clonadas.

02

Primer programa: comprobar que todo funciona

Este programa no necesita componentes: hace parpadear el LED azul de la placa y escribe en el Monitor serie. Cargalo con la flecha (→) y abrí Herramientas → Monitor serie a 115200 baudios.

Programa de prueba · t0_parpadeo.ino
Si el LED parpadea y aparecen los mensajes, el IDE, el driver y la placa funcionan.
/*
  ==========================================================================
  PRIMER PROGRAMA - Comprobar que el IDE y la placa funcionan
  NodeMCU V3 (ESP8266) - Placa en el IDE: "NodeMCU 1.0 (ESP-12E Module)"
  ==========================================================================

  No necesita ningún componente: usa el LED azul que trae la placa
  (LED_BUILTIN = D4 = GPIO2). Ese LED enciende con el pin en BAJO.

  Si el LED parpadea y en el Monitor serie (115200 baudios) aparecen los
  mensajes, el IDE, el driver y la placa están funcionando.
  ==========================================================================
*/

uint32_t contador = 0;

void setup() {
  Serial.begin(115200);
  delay(300);
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.println();
  Serial.println(F("=== La placa funciona ==="));
  Serial.printf("Chip ID: %08X | Flash: %u KB | CPU: %u MHz\n",
                ESP.getChipId(), ESP.getFlashChipRealSize() / 1024, ESP.getCpuFreqMHz());
}

void loop() {
  digitalWrite(LED_BUILTIN, LOW);    // enciende (lógica invertida)
  delay(500);
  digitalWrite(LED_BUILTIN, HIGH);   // apaga
  delay(500);
  contador++;
  Serial.printf("Parpadeo número %lu\n", (unsigned long)contador);
}

Si la carga falla: mantené apretado el botón FLASH de la placa en el momento en que el IDE dice Connecting…. Si sigue fallando con un error de puerto, es el driver: seguí con la parte 3.

03

El problema del driver CH340 y cómo volver al de 2019

El NodeMCU V3 se comunica con la computadora por un chip CH340. Windows Update instala solo las versiones nuevas de su driver (de 2023 y 2024), que no funcionan con muchos chips CH340 clonados, muy comunes en placas económicas. El driver de 2019 sí funciona con esos chips.

3.5.2019.1Funciona con los chips clonados. Es la versión a instalar. La 3.7.2022.1 también funciona.
3.8.2023.2 · 3.9.2024.9Fallan con los chips clonados: la placa aparece en un puerto COM, pero no se puede cargar ni abrir el Monitor serie.

Cómo saber qué versión tenés

  1. Conectá el NodeMCU. Hacé clic derecho en el botón Inicio y abrí el Administrador de dispositivos.

  2. Desplegá Puertos (COM y LPT) y hacé doble clic en USB-SERIAL CH340 (COMx).

  3. En la pestaña Controlador, mirá la Versión del controlador. Si dice 3.8.2023… o 3.9.2024…, seguí con la solución.

Errores típicos de este problema

A fatal esptool.py error occurred: Cannot configure port, something went wrong.
Original message: PermissionError(13, 'Un dispositivo conectado al sistema no funciona.', None, 31)

También aparece como “can’t set com-state” al cargar en un Arduino UNO o Nano con CH340, o como un Monitor serie que no abre.

Solución: instalar el driver de 2019 y revertir

  1. Descargá CH341SER_WIN_3.5.ZIP del repositorio de WEMOS en GitHub: github.com/wemos/ch340_driver. Descomprimilo.

  2. Desconectá internet (WiFi apagado) durante todo el procedimiento, para que Windows Update no reinstale el driver nuevo mientras trabajás.

  3. Ejecutá el instalador que trae el zip con clic derecho → Ejecutar como administrador y presioná INSTALL.

  4. Volvé al Administrador de dispositivos → USB-SERIAL CH340 (COMx) → pestaña Controlador → Revertir al controlador anterior. Como motivo elegí Mis aplicaciones no funcionan con este controlador y presioná Sí.

  5. Si el botón Revertir está gris: Actualizar controlador → Buscar controladores en mi equipo → Elegir en una lista de controladores disponibles en el equipo → elegí el de versión 3.5.2019.1 → Siguiente.

  6. Comprobá en la pestaña Controlador que diga 3.5.2019.1. Desconectá y volvé a conectar la placa, y probá cargar el primer programa.

  7. Recién entonces volvé a conectar internet.

04

Que Windows no lo vuelva a actualizar

Revertir con el botón le indica a Windows que elegiste la versión anterior a propósito, y normalmente no la vuelve a cambiar. Si en las netbooks del aula el problema reaparece después de una actualización, hay una opción más firme.

  1. Abrí Panel de control → Sistema → Configuración avanzada del sistema.

  2. En la pestaña Hardware, presioná Configuración de instalación de dispositivos.

  3. Elegí No (es posible que el dispositivo no funcione como se espera) y guardá.

Tené en cuenta: esta opción frena las descargas automáticas de drivers para todos los dispositivos, no solo para el CH340. En netbooks de laboratorio suele convenir; en una computadora personal, alcanza con revertir.

Con chips CH340 originales el driver nuevo funciona bien: el problema es de los chips clonados. Para comprar placas nuevas, conviene elegir proveedores que usen chips originales.

Fuentes

  • FakeCH340DriverFixer: versiones del driver que fallan con chips clonados (3.8.2023.02 y 3.9.2024.09)
  • Foro de Arduino: error “Cannot configure port” con NodeMCU V3 y CH340
